# Component Guidelines

- Pages are **server components**: they call `requireUser()` and services directly, then pass DTOs to client components. Mark pages `export const dynamic = "force-dynamic"` when they read user data.
- Client components (`"use client"`) handle interaction only and call server actions from `src/app/actions.ts`.
- Named exports, PascalCase components, kebab-case filenames.
- Styling: Tailwind utility classes inline. Color variants must come from `components/colors.ts` (static class strings so Tailwind can detect them) — never build class names like `` `bg-${color}-500` ``.
- Text is Chinese; status labels mirror `describe()` in `lib/days/engine.ts` (「距离 X 还有 N 天」/「X 已经 N 天」/「X 就是今天」).
- Destructive actions use `confirm()` before calling the action. Delete lives in the edit dialog footer (`DayForm` `onDelete`, edit mode only), not on home cards.
- Never combine conflicting width utilities (e.g. a shared `w-full` field class plus `w-20`): Tailwind v4 resolves by stylesheet order, not class order. Keep the shared field class width-less and add the width per use (see `FIELD` in `day-form.tsx`); inline rows of fixed controls use `shrink-0` + `whitespace-nowrap`.

- **Semantic tokens, not raw neutrals.** Neutral/UI colors come from the CSS variables in `app/globals.css` exposed through `@theme inline`: `bg-bg`, `bg-surface`, `bg-surface-2`, `border-border` (inputs/chips), `border-line` / `divide-line` (dividers, card outlines), `text-fg`, `text-muted`, `text-subtle`, `bg-accent text-accent-fg` (+ `hover:bg-accent-hover`), `text-danger` / `bg-danger-soft` / `border-danger-line`, `warn-*`, `bg-code text-code-fg`, `ring`, `bg-overlay`. Do not use `stone-*`, `bg-white`, `red-*` in components; tokens switch automatically in dark mode. Exception: white-on-gradient text inside the hero card (`text-white/…`).
- **Shared class strings** live in `components/styles.ts` (`FIELD`, `BUTTON_PRIMARY`, `BUTTON_GHOST`, `HEADER_BUTTON`, `ERROR_BANNER`, `PANEL`). They are width-/padding-less where callers need to size them — add `w-*` / `p-*` per use, never a second conflicting utility.
- **Dark mode.** Theme = system / light / dark, stored in `localStorage["lovedays-theme"]` (per device). `THEME_INIT_SCRIPT` (`components/theme.ts`, inlined in `app/layout.tsx` `<head>`) sets `<html data-theme data-theme-pref>` before first paint and follows OS changes while pref = system. `dark:` is a custom variant bound to `[data-theme=dark]` (not the media query). Read/change the preference only via `useThemePref()` (`hooks/use-theme-pref.ts`); UI: `ThemeToggle` (header) and `ThemeSelect` (settings 「外观」).
- **Category colors** stay in `colors.ts` as static strings and carry their own `dark:` variants (e.g. `bg-rose-50 border-rose-200 dark:bg-rose-500/10 dark:border-rose-400/25`). Any new category style must include both modes.
- **Icons** come from `lucide-react` (named imports, `aria-hidden` when decorative, `role="img" aria-label` when meaningful). No emoji or text glyphs (`+`, `←`, 📌) as icons.
- **Display font**: `font-display` (Outfit, self-hosted via `@fontsource-variable/outfit`) only for day-count numbers and page/dialog titles; numbers keep `tabular-nums`. Chinese body text uses the system stack.
- **Motion**: keyframes/`--animate-*` are registered in `globals.css` (`fade-in/out`, `sheet-up/down`, `pop-in/out`). Movement (translate/scale) must be gated with `motion-safe:`; give `motion-reduce:` an opacity-only fallback. Dialogs (`DayForm`) play an exit animation before calling `onClose` (with a timeout fallback), close on Esc and overlay click, and lock body scroll while open.
